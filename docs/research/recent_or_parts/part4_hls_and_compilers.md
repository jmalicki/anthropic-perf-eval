## 0. Bottom line

- The HLS exact-scheduling literature (SDC+SAT, Moovac, graph preprocessing) is tuned for a regime unlike ours: few resource-limited operations (3 % to 29 % of ops in Oppermann's set), capacities of 1 to 8, and at most a few hundred contended ops. In our problem every op is resource-limited and capacities are 12/6/2/2/1. Its machinery is either already inside CP-SAT (difference-logic propagation with explanations) or relies on an encoding (per-instance binding + pairwise ordering) that is worse than a cumulative for our capacities.
- The most useful evidence is not a paper. One public repository reaches **975 cycles against a 967-cycle capacity floor for its op stream (8 cycles, 0.8 %)** with a priority-searched list scheduler plus backward/forward justification and **zero solver calls**; its whole-problem exact query (Z3) ran out of memory after 16 h 52 min. Our gap to our own floor is 43 to 128 cycles. So (i) near-floor packing of this DAG family is reachable by search over list-scheduler priorities, and (ii) the public sub-1,000 results are mostly an emission result (fewer ops, engines balanced), not a scheduling result.
- No public write-up was found that uses CP-SAT, ILP, MiniZinc or a SAT scheduler on this challenge. One used Z3 for a 527-variable repair, one used beam search, the rest list scheduling.

## 1. HLS scheduling

### 1.1 SDC scheduling and its exact successor (SDC + SAT)

**Sources.**
- Dai, Liu, Zhang, "A Scalable Approach to Exact Resource-Constrained Scheduling Based on a Joint SDC and SAT Formulation", FPGA 2018. https://www.csl.cornell.edu/~zhiruz/pdfs/sds-fpga2018.pdf - **full text** (10 pages).
- Dai, Zhang, "Improving Scalability of Exact Modulo Scheduling with Specialized Conflict-Driven Learning", DAC 2019. https://www.csl.cornell.edu/~zhiruz/pdfs/sdsp-dac2019.pdf - **full text** (6 pages).
- Cong, Zhang, "An Efficient and Versatile Scheduling Algorithm Based on SDC Formulation", DAC 2006 - **not opened**; described here only as Dai et al. section 2.1 describes it.

**What it is.** SDC scheduling gives each op a start variable and writes dependence and timing constraints as `s_i - s_j <= b`; the matrix is totally unimodular, so an LP gives integer schedules. Resource limits do not fit that form, so plain SDC imposes one heuristically chosen linear order among the resource-constrained ops as extra difference constraints (Dai et al. sec. 2.1, Fig. 2), with no optimality guarantee. Dai et al. make it exact: SAT variables `B_ik` (op i bound to resource instance k), derived sharing variables `R_ij`, and ordering variables `O_i->j` with clauses `R_ij -> (O_i->j or O_j->i)`. A true `O_i->j` adds the edge `s_i - s_j <= -1` to an incremental SDC constraint graph; a negative cycle is infeasibility, and the `O` literals on that cycle become a learned clause. Latency is minimised by binary search between an SDC-heuristic upper bound and a "resource-aware lower bound" (Rim and Jain). Two specialisations matter: (1) the lower-bounding routine runs after each edge insertion and can refute a partial binding with fewer edges than a negative cycle would need, giving shorter clauses; (2) **incremental learning**: start with no resource constraints at all, schedule with SDC, check legality, repair with a list-scheduling pass, and add SAT variables only for the ops still in contention.

**Reported sizes and effects** (FPGA 2018 Table 1; 300 s timeout; Lingeling; resource limits on multipliers and memory ports):

| Benchmark | #ops | SDS non-incr. | SDS incremental (% of SAT vars used) | CPLEX | CBC | Optimal vs LegUp SDC latency |
|---|---|---|---|---|---|---|
| ARAI | 44 | 0.01 s | 0.01 s (39.5 %) | 0.12 s | 1.18 s | 8 vs 9 |
| HONDA | 105 | 0.02 s | 0.02 s (0.95 %) | 9.06 s | 104 s | 27 vs 33 |
| CHEM | 349 | timeout | 1.42 s (0.12 %) | timeout | timeout | 85 vs 89 |
| U5ML | 857 | 0.01 s | 0.01 s (0.00 %) | 20.8 s | timeout | 261 vs 264 |

The abstract claims "on average over 100x improvement in runtime over the ILP approach". The authors note U5ML is easy because it is "much more constrained by timing than by resource", and that in incremental mode "mostly less than 10 % of the SAT variables are needed". Table 2 varies resources from 1 multiplier / 1 port to 6 / 6 only. On CHStone inside LegUp (Table 3, up to 2,255 ops) runtimes are 0.01 to 0.11 s, but the paper says those benchmarks "are not dominated by resource constraints".

DAC 2019 extends this to modulo scheduling (ordering variables carry an iteration distance k; conflicts are again negative cycles) and adds an SCC-based graph reduction: only cyclic components containing resource-constrained ops need the exact solver. On 350 loops from CHStone and MachSuite (timeout 15 min or 10x SDS+ runtime): ADPCM1 (777 ops, 108 resource-constrained) default ILP and reduced ILP time out, SDS+ 31.1 s, reduced SDS+ 11.9 s; DFSIN1 (2,651 ops / 74 resource-constrained, reduced to 115 / 74) is solved only by reduced SDS+ in 606 s. The paper states ILP becomes "difficult to solve as the total number of operations increases beyond 400 or the number of resource-constrained nodes goes beyond 50".

**Does CP-SAT 9.15 have it?** The theory half, yes. Installed header `/opt/homebrew/Cellar/or-tools/9.15_17/include/ortools/sat/old_precedences_propagator.h` (**source code**, read) documents `PrecedencesPropagator` as a propagator for `i1 + offset <= i2` using "an incremental variant of the Bellman-Ford(-Tarjan) algorithm", states "This is also known as an 'integer difference logic theory' in the SMT world", and declares `AnalyzePositiveCycle(..., literal_reason, integer_reason)`, i.e. cycle conflicts are explained to the SAT core. The same header says it is "superseded by the new LinearPropagator" unless `new_linear_propagation` is false. So negative-cycle conflict learning over difference constraints is subsumed. How it differs from lazy clause generation: SDS is an offline-style DPLL(T) loop (SAT proposes a set of orderings, SDC accepts or returns one cycle clause over ordering literals); CP-SAT propagates bounds eagerly at every node and explains each bound change with bound literals, so it learns the same cycle conflicts earlier, plus nogoods over start-time bounds that SDS cannot express. [my reasoning] The resource half is where they differ: SDS has no cumulative; it encodes capacity as binding to instances plus pairwise orderings. That is O(n^2) ordering variables per resource class and has k! instance symmetry. For 2 memory ports and a few dozen contended ops it is fine; for 12 scalar slots and thousands of unit-duration ops CP-SAT's timetable cumulative is the stronger encoding. **CP-SAT subsumes SDS on our problem**, with two exceptions that CP-SAT does not do by itself:

1. *Contention-driven lazy model growth* (SDS "incremental learning"). CP-SAT explains lazily but always loads every interval into every cumulative.
2. *A resource-aware lower bound used as a conflict source* (Rim and Jain inside the theory). The other survey agent covers Rim and Jain; I only note that Dai et al. report it shortens conflict clauses, and that it is the one ingredient aimed at what we lack (a bound above the capacity floor).

**Application to us.** Exception 1 maps to: solve without the memory cumulative (and without cumulatives for engines far from binding, e.g. store: one public kernel has 32 store ops against a 16-cycle store floor), check the incumbent, and add the memory constraint only over cycle ranges and values where the check fails. **Benefit:** (i) finding - possibly large at 12K ops if the sixth cumulative with variable-length intervals is what makes the full model unsearchable; unknown until measured; (ii) proving - none (a relaxation can only lower the bound). **Route:** outer loop around CP-SAT; no fork. **Honest caveat:** in our model the contended fraction is near 100 %, not under 10 %, so the SDS speedups do not transfer.

### 1.2 Problem reduction before exact scheduling

**Oppermann, Reuter-Oppermann, Sommer, Sinnen, Koch, "Dependence Graph Preprocessing for Faster Exact Modulo Scheduling in High-Level Synthesis", FPL 2018.** https://www.esa.informatik.tu-darmstadt.de/assets/publications/materials/2018/2018_FPL_JO.pdf - **full text**.
Keep only "critical" ops Q (resource-limited ops, back-edge endpoints, sources and sinks); replace every subgraph of non-critical ops by a single edge whose delay is the longest path through it; drop edges implied transitively (Floyd-Warshall on Q); schedule the reduced graph exactly; complete the rest by an SDC. On 21 instances (median 471 ops, 1,578 edges; resource-limited share 3 % to 29 %, median 12 %) the Eichenberger-Davidson time-indexed ILP shrinks to 15 % of variables and 22 % of constraints (geometric means) and speeds up by a geometric mean of 4.37x (up to 14x); the Moovac formulation is not helped (geometric mean 0.80x) because it already models unlimited ops with one integer each.
*For us:* every op consumes a typed slot, so Q is everything. It applies only to ops of a class we choose to treat as unlimited. CP-SAT's presolve already removes transitively implied precedences in places (`transitive_precedences_work_limit` exists in `sat_parameters.pb.h`; I did not read what it gates). **Benefit: small.**

**Sittel, Fiege, Kumm, Zipf, "Isomorphic Subgraph-based Problem Reduction for Resource Minimal Modulo Scheduling", ReConFig 2019.** DOI 10.1109/ReConFig48160.2019.8994768. **Abstract only** (via the Semantic Scholar API record https://api.semanticscholar.org/graph/v1/paper/DOI:10.1109/ReConFig48160.2019.8994768 and the IEEE Xplore search listing; the IEEE page returned no body and no open PDF was found; author list from Crossref). The abstract says the input data-flow graph is reduced "based on isomorphic subgraphs" before modulo scheduling, leaving the optimal initiation interval and allocated hardware unchanged; reported effects: solving-time speedup about 5x on average and up to 102x for large designs; for SDC-based modulo schedulers the achieved II improves by 33 % on average; for ILP-based scheduling 15 % more solutions are classified optimal in the same time. **I could not read how the subgraphs are found or what exactly is collapsed, so I will not describe the mechanism.** This is the paper most directly about our structure; someone with IEEE access should read sections III and IV. What I can say is that its objective differs from ours: it minimises allocated resources for a given II (hardware is the variable), whereas our capacities are fixed and makespan is the variable. A reduction that is exact for "how many units are needed" need not be exact for "how short can the schedule be".

**CP-SAT 9.15:** has symmetry detection (`cp_model_symmetries.h`, `symmetry_level`) but, as far as the header list shows, no structural collapse of identical subgraphs [my inference from the installed headers, not a maintainer statement].

**How the idea would apply to us [my reasoning].** With 32 identical groups coupled only by capacities and memory, the natural reduction is a *template plus offsets* model: one relative schedule for a group (start variables for 1/32 of the ops), one integer offset per group, resource use = sum of shifted copies of the template's profile. Any solution is feasible for the full problem (an upper bound), and it is a restriction, so it proves nothing. Strictly equal offsets (offset_g = g * II) is modulo scheduling; see 1.3 for why that particular restriction is too tight in our regime.

### 1.3 Modulo (periodic) scheduling

**Sources.** Oppermann, Reuter-Oppermann, Sommer, Koch, Sinnen, "Exact and Practical Modulo Scheduling for High-Level Synthesis", ACM TRETS 12(2), 2019, https://www.esa.informatik.tu-darmstadt.de/assets/publications/materials/2019/2019_TRETS_JO.pdf - **partial** (abstract and introduction, pages 1-2). Dai and Zhang DAC 2019 - full text (above). Canis, Brown, Anderson, "Modulo SDC scheduling with recurrence minimization in high-level synthesis", FPL 2014 - **snippet only** (SDC formulation with backtracking to legalise against the modulo reservation table). Sittel, Kumm, Oppermann, Möller, Zipf, Koch (author list not fully confirmed), "ILP-based Modulo Scheduling and Binding for Register Minimization", FPL 2018 - **snippet only**: register count added to the ILP objective, 30.4 % fewer registers than minimum-lifetime approaches at under 4 % extra scheduling time. Oppermann et al. CASES 2016 - not opened.

**What it is.** One schedule for a single iteration, repeated every II cycles; resource limits must hold per congruence class of start times modulo II (the modulo reservation table). The TRETS introduction gives the latency of n iterations as `(n - 1) * II + T`, T being the single-iteration schedule length. TRETS abstract: 188 loops, proven-optimal IIs for 179, under 16 minutes accumulated in the fastest configuration.

**CP-SAT:** no modulo-scheduling constraint; it can be modelled (start = q * II + r with a cumulative or cardinality rows over r). [my reasoning]

**Application to us [my reasoning; numbers are from the brief].** Two candidate periodic axes:
- *Across the 32 groups.* Floor 1,271 / 32 gives II of about 40, but a group's critical path is T >= 264, so `(n-1)*II + T` is about 31*40 + 264 = 1,504: worse than what we have. A strict group-periodic schedule wastes the ramp (T - II is about 224 cycles of under-filled start and tail). Good schedules must run early groups dense and later ones stretched; one write-up describes exactly such a "wavefront" (section 3). **Not recommended.**
- *Across rounds.* All 32 groups execute round r inside a band of about 1,271 / 16 = 80 cycles, while one round's critical path is only about 264 / 16 = 16.5. The ramp loss is then paid about once, not 32 times, and its size (tens of cycles) is in the range of our observed gap of 43 or more. Rounds are not all identical (tree depth changes the access encoding), so this is periodicity over classes of rounds. The per-round sub-problem (about 12K / 16 = 750 ops) is the size our 25-cycle windows already solve to optimality in seconds.

The memory limit folds too: with II much smaller than value lifetimes, the live-word count at steady state is the template's live profile summed over its wrap-arounds, a constraint over one template. **Benefit:** (i) finding - a structured incumbent whose only waste is at the two ends and at round-class transitions, where windowed CP-SAT can then work; (ii) proving - none directly. **Route:** small separate CP-SAT model plus stitching, then hint. **Effect sizes in the papers** concern II minimisation for loops, not finite-batch makespan; they do not transfer.

**What this says about our problem [my reasoning].**
1. ## 4. Techniques that neither plain CP-SAT nor a greedy list scheduler gives us

**(a) SDC+SAT lazy conflict learning.** Subsumed by CP-SAT for the precedence theory (difference-logic propagator with explained cycle conflicts, section 1.1); its resource encoding is weaker than a cumulative at our capacities. Not subsumed: contention-driven lazy introduction of resource constraints, and the Rim-Jain bound as a conflict source. Reported: over 100x versus ILP on 44 to 857 ops with 1 to 6 units per resource.

**(b) Isomorphic-subgraph reduction.** Sittel et al. report 5x average, up to 102x, but I could only read the abstract and its objective is resource minimisation at fixed II. CP-SAT has symmetry detection, not structural collapse. Our analogue is a template-plus-offsets restricted model (upper bounds only).

**(c) Modulo schedule plus boundary.** Not in CP-SAT. Periodic across groups is the wrong axis (about 1,504 by the `(n-1)*II + T` formula); periodic across rounds is plausible and matches the size of windows we can already solve.

**(d) DP with adaptive windowing.** Exact only for sequential peak-memory ordering on graphs under about 100 nodes. Not applicable. The transferable piece from that family is MODeL's time-indexed liveness rows.

**(e) Force-directed / ant-colony / metaheuristic warm starts.**
- Wang, Gong, DeRenzi, Kastner, "Ant Colony Optimizations for Resource- and Timing-Constrained Operation Scheduling", IEEE TCAD 26(6), 2007, https://cseweb.ucsd.edu/~kastner/papers/tcad07-aco_operation_scheduling.pdf - **partial** (pages 1021-1025: experiments). Max-min ant system in which pheromone ties an op to a position in the priority list handed to an ordinary list scheduler; 10 ants, 100 iterations. Those DFGs are at most 354 nodes with 1 to 15 units, so the percentages do not transfer. The mechanism (learn a priority order, evaluate with a fast list scheduler) is the one the 975-cycle repository uses in deterministic form. For large regular DAGs the best-evidenced recipe is: **list scheduling + backward/forward justification + search over a low-dimensional priority and mode space**. Sharing learned priorities across the 32 identical groups (op class x group phase, not 12K x 12K) is the adaptation our regularity allows. [my reasoning] CP-SAT has no equivalent; the route is our Rust greedy scheduler, then hints.

## 5. Ranked ideas from this topic, each with a cheap experiment

1. **Backward/forward justification and priority search in the greedy scheduler, measured against the emission's capacity floor.** Evidence: 975 on a 967 floor with zero solver queries, where exact search failed. Experiment (no solver): take an existing 16-round schedule JSON; right-justify every op as late as capacities, precedence and memory allow in reverse order of finish, then left-justify in order of start; repeat until no change and count cycles saved. Then randomise three or four priority weights over about 100 runs and record the spread (another author measured 11 cycles of pure scheduler noise). Use the lift-and-reschedule tool on a public kernel to check that our scheduler gets as close to that kernel's floor as its author's did.
2. **Treat emission/mode balance as the primary search dimension, scheduler as evaluator.** Evidence: the best public kernel has all four engine floors within 23 cycles of each other; our window gains come from mode changes. Experiment: from one schedule JSON compute per-engine floors per 100-cycle decile; if one engine is at 100 % while another is under 90 %, enumerate the few mode toggles that move work between them and re-run greedy only.
3. **Round-periodic template plus boundary windows.** Experiment (one small CP-SAT model, not a heavy job): take one class of structurally identical consecutive rounds (about 750 ops for 32 groups), unroll three copies with equal offsets II, fix II = ceil(round work / capacity) for the binding engine, add the folded live-word limit, and ask for feasibility at II, II+1, II+2. If II at the floor is feasible, the whole gap lives at the ends and class transitions; if not, the minimal feasible II times the number of rounds is an estimate of what any round-banded schedule can reach.
4. **Lazy memory constraint (the transferable part of SDS).** Experiment: at 2 to 4 rounds, solve with the sixth cumulative removed; measure peak live words of the result. If it is under 1,536 or only locally over, add memory rows only for offending cycle ranges and re-solve with the hint. Compare time-to-incumbent with the full model at equal deterministic time using the existing ablation harness.
5. **MODeL-style time-indexed liveness rows inside windows.** Experiment: in the window probe (W = 25, about 900 ops), replace the variable-length-interval memory cumulative with per-(value, cycle) live booleans and one linear row per cycle; compare proof time and the bound on the windows that currently cannot be shortened.

Lowest priority: porting SDC+SAT itself, dependence-graph preprocessing, DP ordering, CGRA mappers, force-directed scheduling.
